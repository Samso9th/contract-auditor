## The asset that makes it possible

Most agents cannot self-improve because nothing ever tells them they were wrong.
An agent that reads code and reports problems produces opinions, and opinions
have no gradient.

This project has an oracle. Every claim is charged the price of a Go test, and
the outcome is a free, unambiguous label produced at runtime with no human in the
loop:

| Gate verdict | Label |
|---|---|
| `confirmed` | true positive |
| `refuted` | **false positive** |

<Card icon="scale-balanced">
  **Memory adjusts priors. The gate still decides.**

  Learned history may change what the auditor looks at and how it ranks a
  finding — but it must never hard-suppress a claim. If the model still makes the
  claim and the test still fails, the drift is real, and yesterday's statistics
  do not get a veto over today's evidence.
</Card>

## Five mechanisms

<Steps>
  <Step title="The claim ledger">
    Append-only JSONL of every claim ever made, **including the discarded ones** —
    which are the valuable half. The only component that is expensive to add
    later: reconstructing rejected claims from runs that never logged them means
    paying for every run again.
  </Step>
  <Step title="Retrieval of past mistakes">
    Before auditing an endpoint, pull the most similar previously refuted claims
    into the prompt: *these looked like drift and were not.* Keyed on structural
    shape rather than raw text, which keeps it deterministic and dependency-free.
    This is where most of the precision gain lives.
  </Step>
  <Step title="Promoting dismissals into rules">
    When several allowlisted items share a shape, promote it to a rule carrying
    its own support count — `routes under /admin/* are internal`, support 47.

    This produces the internal-vs-public classifier as a **learned artifact
    instead of a hand-written config**, with auditable evidence behind each rule.
  </Step>
  <Step title="Calibration, not learning">
    Track each claim kind's survival rate through the gate, and let it drive
    severity ranking and verification budget. Pure arithmetic — no training, and
    completely explainable to someone who has to trust the output.
  </Step>
  <Step title="Growing the evaluation set from the field">
    Every confirmed real drift becomes a new mutation; every false positive that
    survived becomes a new decoy. Nearly every self-improving agent improves the
    policy while the benchmark stays frozen, at which point rising scores are
    indistinguishable from overfitting. Growing the test set alongside the agent
    is what makes the trend line mean anything.
  </Step>
</Steps>

## The failure mode worth naming

<Warning>
  **Feedback poisoning.** Suppress a claim class because it has historically been
  wrong, and the auditor stops producing claims of that class — which means it
  generates no counter-evidence — which means the suppression is never
  contradicted. The belief becomes permanently self-justifying, and the blind
  spot is invisible from inside: precision looks excellent, because the misses
  are no longer being counted.
</Warning>

The fix is cheap. **Epsilon exploration:** audit ~5% of endpoints with memory
disabled entirely, purely to keep measuring the classes memory has learned to
skip. If a suppressed class starts confirming again, the rule that suppressed it
gets demoted. This is why rules store support counts — a rule you cannot
re-evaluate is a rule you cannot retire.

## What to skip

**Fine-tuning on the ledger.** The data will be dozens to low hundreds of
labelled examples, the base models are already strong at the task, and a
fine-tune freezes the project out of model upgrades that have been arriving
faster than any training loop here would converge. Retrieval beats fine-tuning
decisively in this regime.

## The demo

Run the same case set twice. The second run should score higher precision,
because the false positives from run one were retrieved as negatives in run two.
Self-improvement with a number attached, in about two minutes.
