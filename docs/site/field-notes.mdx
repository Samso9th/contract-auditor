Each of these cost real debugging time, and none were discoverable by reading
documentation. Recorded so the same hour is not spent twice.

<AccordionGroup>
  <Accordion title="GLM 5.3 Flash's reasoning cannot be turned off" icon="brain">
    `reasoning: {enabled: false}` returns **HTTP 400**.

    The model thinks in *output* tokens, so a tight `max_tokens` truncates the
    thinking rather than the answer, and the reply arrives as `content: null`
    with `finish_reason: "length"`.

    **Resolution.** Default is now 8000 tokens, and the client reports truncation
    as its own distinct condition rather than surfacing it as a bad answer — the
    two need different handling and look identical from the outside.
  </Accordion>

  <Accordion title="kimi-k2.7-code prefixes its JSON with a space" icon="code">
    The extractor handles a leading space, code fences, prose on either side, and
    braces appearing inside strings.

    That last one is the case a naive `rfind("}")` gets wrong — it will happily
    cut a JSON document at a brace that is inside a string literal.
  </Accordion>

  <Accordion title="Python HTTPS is pathologically slow here" icon="gauge-high">
    System Python 3.9 links **LibreSSL 2.8.3**. Both `urllib` and `requests` took
    ~160s for calls `curl` completes in 3–7s.

    The earlier read — "the models are slow" — was wrong. The tell was six
    different models all landing at 153–160s regardless of whether they emitted
    40 tokens or 854. That is not model latency; that is a fixed transport cost
    wearing a disguise.

    **Resolution.** Transport is `curl` throughout, which has the side benefit of
    keeping the whole harness dependency-free.
  </Accordion>

  <Accordion title="claude-haiku-4.5 did not honour json_object via OpenRouter" icon="triangle-exclamation">
    Recorded so nobody picks it as a fallback expecting structured output.
  </Accordion>
</AccordionGroup>

## The common thread

In all four cases the plausible explanation and the correct one were different,
and only measurement separated them.

The third is the sharpest: a confident, reasonable, entirely wrong diagnosis that
would have survived any amount of further thinking about it. Which is the same
thesis the [verification gate](/verification-gate) rests on, arriving from the
other direction.
